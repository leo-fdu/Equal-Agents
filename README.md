# Equal Agents — macOS 0.1

原生 SwiftUI 多 agent 讨论应用。macOS 14+，当前交付为 Apple Silicon 构建。

## 使用

1. 打开 `Equal Agents.app`。应用内置 Node 运行时，无需为后台另装 Node。
2. 本机需要安装并登录 Codex 或 pi。应用沿用框架自己的登录及渠道设置，不保存凭据。
3. 新建会议：配置一位主持人、2–8 位参会者、可选身份提示词、1–12 轮第二阶段讨论及共享区开关。界面为英文；讨论语言跟随主题。
   每位成员先选择 Codex / pi；pi 单独选择渠道。模型 ID 可直接输入，输入过程中显示当前框架和渠道的匹配建议。
   时间与篇幅默认均为 No limit，也可打开限制。模型本身的上下文和服务限制仍然适用。
4. 可在共享资料页导入 PDF、UTF-8 文本、JSON 或 HTML 附件，然后开始。
5. 失败会暂停；继续只重试未完成发言。允许明确跳过失败的参会者发言。主持环节不能跳过。可在 Participants 中更换后续发言的模型，已完成的发言保留原模型记录。
6. 使用导出菜单保存 Markdown 完整会议记录或最终报告。
7. 右键讨论选择 Delete discussion，或点击窗口顶部的垃圾桶。运行中的讨论会先停止；删除后进入 Recently Deleted，可恢复。记录和共享资料保留，不会自动永久清除。

## 会议规则

- 主持人只有开场和报告两次发言，无工具权限。
- 第一阶段并行独立提案，每位一次。屏蔽其他人的提案与本阶段新增资料。
- 第二阶段每轮按席位顺序发言；每位每轮一次，接收全部已完成的先前发言。
- 第三阶段每位顺次总结一次，回应最后一轮遗留质疑，不再研究或发起新争论。
- 报告使用完整记录。不会从缺席或沉默推断同意。
- 可公开发言次数为 `2 + N × (R + 2)`。工具调用不计作公开发言；框架内部调用可能多于此数。
- 完整提示超过 220,000 字符时暂停，不静默截断。该保护上限不是对每个模型上下文容量的精确估算；模型自身限制也可能导致暂停。
- 每次发言最多 24 次资料工具调用。每次调用有网络与大小限制。

## 共享资料

开启时，检索返回的全部结果及读取的正文在交付模型前登记。初始提案阶段仅用户附件与自己的资料可读，进入讨论后共享所有资料。每条记录保留来源、摘要/正文类型、发现者与内容哈希；读取记录仅证明返回了哪些片段，不证明理解。

搜索使用 Bing 公开 RSS 搜索入口；可用性与结果质量取决于服务和网络，失败会明确返回错误。当前不是完整浏览器，不能处理登录页、验证码或 JavaScript 才生成的正文。链接 PDF 暂需用户下载后导入；本机 PDFKit 提取正文，不包含 OCR。

关闭时，检索资料仅在当前发言的临时内存中可用，不写入共享资料库。最终发言中的引用仍会保存在会议记录中。

没有 agent 个人工作区，也没有执行 shell / 脚本的工具。内部 `runtime` 目录只用于启动框架，不向模型暴露。会议信息默认保存在 `~/Library/Application Support/Equal Agents`，采用逐会议原子 JSON 快照。讨论与附件不会写入 Research OS 数据库。模型请求和搜索会访问相应网络服务。

## 构建与测试

```sh
node --test tests/*.test.mjs
./build_app.sh
```

需要 Xcode / Swift 5.9+ 和一个独立 Node.js 22+ 运行时。默认使用 Codex 桌面运行时里的 Node；可用 `EQUAL_AGENTS_BUNDLE_NODE` 指定其他独立二进制。构建脚本将 Node 及其许可证一起放入 app。

运行时覆盖：`EQUAL_AGENTS_CODEX`、`EQUAL_AGENTS_PI` 可指定 CLI 路径；`EQUAL_AGENTS_DATA` 指定隔离的数据目录；`EQUAL_AGENTS_ENGINE` / `EQUAL_AGENTS_NODE` 用于开发。

源码分层：`Sources/EqualAgents` 为原生界面；`engine/core.mjs` 为严格调度与持久化；`runtime.mjs` 为 Codex app-server / pi RPC；`sources.mjs` 为受控资料工具；`server.mjs` 为界面通信与工具桥。后台使用标准 ECMAScript 模块，无第三方 npm 依赖，后续 Windows 界面可复用。

## 发布边界

本构建为本地 ad-hoc 签名，未公证。Codex / pi 协议依赖安装的框架版本；启动失败不会静默切换模型。当前版本不包含 Windows 界面、云同步、账户登录界面、自动升级、OCR、脚本执行或研究项目系统。

会议调度保证发言次数与可见上下文；回应是否有说服力、模型是否准确理解证据仍属于模型输出质量。身份提示不会成为高于会议协议的指令。

### 模型选择
先选 Codex 或 pi；pi 再选渠道。点击 Model 打开搜索浮层，输入名称或模型 ID 即时筛选（例如 `gpt6`）。支持上下方向键、Enter 选中和 Escape 关闭。目录中没有的模型可输入完整 ID 后选择 Custom Model。最近选择会保存在本机并按框架和渠道显示；同一编辑表单内切换框架或渠道会保留各自的模型和推理配置。

### 初始材料与私有人格
创建讨论时可添加 PDF、UTF-8 文本文件和 HTTP/HTTPS 链接；文件会提取全文，所有初始材料独立于共享区开关，提供给主持人与每位参会者。初始材料最多 20 项、合计 100,000 字符；更大文件可在创建后添加到共享资料区。链接不是已读取的网页正文，参会者需在研究阶段读取相关链接。扫描 PDF 暂不支持 OCR。
人格编辑框支持多行输入与滚动。模型上下文只包含本人的人格，其他参会者名单仅包含 ID 和姓名；主持人也不会收到人格。公开发言仍会进入后续讨论记录。
手动滚动讨论正文或拖动滚动条会暂停自动跟随；点击底部 Jump to latest 返回最新内容并恢复跟随。
